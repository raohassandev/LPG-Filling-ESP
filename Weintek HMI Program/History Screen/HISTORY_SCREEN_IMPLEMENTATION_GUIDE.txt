  LPG FILL HISTORY SCREEN — IMPLEMENTATION GUIDE
  Screen: "Fill History" (Reports tab), resolution 800 × 480
  Controller device in EBP: LPG-Controller (Modbus TCP 192.168.0.100:502)
  ProcessState enum on wire: Idle=1, FillingFast=4, FillingSlow=5,
                              Settling=6, Complete=7, Aborted=8, Fault=9
═══════════════════════════════════════════════════════════════════════════════

OVERVIEW
--------
The controller stores the result of every fill (success, abort, fault) in a
21-register block starting at 4x,156 (PDU 0x009C).  After each fill the
firmware sets 4x,175 (PendingAck) = 1 to signal "new record ready".
The HMI must:
  1. Read and display the block (direct display objects work without macros).
  2. Write any non-zero value to 4x,176 (RecAck) to clear the flag.
  3. Clear local bit LB1506 to reflect the acknowledged state locally.

The block is NOT a FIFO — it is overwritten on each fill.  If you need
persistent history, copy the block to retentive LW registers (RW space)
inside M07 before acknowledging, or use the ESP32 web API
GET /api/transactions to pull the full transaction log.

STEP 4 — MACROS
═══════════════════════════════════════════════════════════════════════════════
Two macros are needed. Both are in:
  History Screen/04_Macros/M07_Fill_Record_Acknowledge.txt

── M06_Poll_Fill_Record (periodic, 500 ms) ──────────────────────────────────
Create a new Cycle macro (Macro → Add → Cycle Macro, interval 500 ms).
Assign it to the Fill History screen (run only when screen is open).
Paste the "M06_Poll_Fill_Record" code from the macro file.

What it does: reads 4x,175 (PendingAck) every 500 ms and mirrors it to
LB1506.  This drives the "Pending lamp" and ACKNOWLEDGE button visibility.

Alternative: If EBP supports Data Change Triggers, set a trigger on
4x,175 changing to 1 → call M07 directly, skipping the poll loop.

── M07_Fill_Record_Acknowledge (button macro) ───────────────────────────────
Create a new Macro (Macro → Add).
Paste the "M07_Fill_Record_Acknowledge" code from the macro file.
Assign it to the ACKNOWLEDGE function key button's "Press" event.

What it does:
  1. Reads 4x,175 (PendingAck) — skips if already 0.
  2. Writes 1 to 4x,176 (RecAck) — firmware clears pendingAck.
  3. Clears LB1506 — hides the pending indicator and disables the button.


═══════════════════════════════════════════════════════════════════════════════
STEP 5 — ACKNOWLEDGE BUTTON VISIBILITY
═══════════════════════════════════════════════════════════════════════════════
The ACKNOWLEDGE button should be greyed-out / hidden when no record is
pending. In EBP, add a Visibility condition:

  Object: ACKNOWLEDGE Function Key button
  Visibility condition: LB 1506 == 1
    → Button visible and active when LB1506 = 1 (pending record exists)
    → Button hidden or disabled when LB1506 = 0

Alternatively, use "Bit lamp" to swap between two button states (greyed vs
coloured) using LB1506 as the control bit.

STEP 7 — WORD LAMP STATES FOR "Status" FIELD
═══════════════════════════════════════════════════════════════════════════════
"Fill Rec Result" (4x,158) uses kHmiResult_* codes:

  Value | Label    | Background colour
  ------|----------|------------------
    0   | —        | Grey    (idle / no data yet)
    1   | Accepted | Blue    (should not appear in record)
    2   | Busy     | Blue    (should not appear in record)
    3   | Rejected | Orange
    4   | Done     | Green   ← normal successful fill
    5   | Failed   | Red     ← fault terminated

For the "Mode" word lamp (4x,160):
  Value | Label
  ------|----------
    0   | By KG
    1   | By Amount

═══════════════════════════════════════════════════════════════════════════════
STEP 9 — OPTIONAL: SAVE RECORD TO RETENTIVE MEMORY
═══════════════════════════════════════════════════════════════════════════════
The controller overwrites registers 4x,156–176 on every fill.  If you want
to show the last N records on the HMI (without the web API), modify M07 to
copy the register values to RW (retentive) space before acknowledging:

  RW1000–RW1001  → Record ID Hi/Lo copy
  RW1002         → Result
  RW1003         → Mode
  RW1004         → Error Code
  RW1005–RW1006  → Actual KG (float hi/lo)
  RW1007–RW1008  → Final Amount (float hi/lo)
  RW1009         → Duration Lo (seconds)

Use GetData to read each 4x tag then SetData to write to RW addresses
before calling SetDataEx to write the ack.  RW values survive power cycles.

  PDU   | Dec | Tag                   | Type    | R/W
  ------|-----|-----------------------|---------|----

  00A0  | 160 | Fill Rec Mode         | UINT16  | R
  00A1  | 161 | Fill Rec Target KG    | FLOAT32 | R  (Hi at 161, Lo at 162)
  00A3  | 163 | Fill Rec Actual KG    | FLOAT32 | R  (Hi at 163, Lo at 164)
  00A5  | 165 | Fill Rec Rate Per KG  | FLOAT32 | R
  00A7  | 167 | Fill Rec Target Amt   | FLOAT32 | R
  00A9  | 169 | Fill Rec Final Amt    | FLOAT32 | R

  00AD  | 173 | Fill Rec Dur Hi       | UINT16  | R
  00AE  | 174 | Fill Rec Dur Lo       | UINT16  | R
